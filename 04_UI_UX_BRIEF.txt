DOCUMENT 04 — UI/UX DESIGN BRIEF

Project: Automated Audit Evidence Retrieval
Version: 1.0

1. DESIGN DIRECTION
Professional enterprise audit application.
Clean, modern, trustworthy, structured, information-dense without being crowded.
Desktop-first internal tool.

2. DESIGN PRINCIPLE
The UI must always make three things clear:
1. What did the auditor ask?
2. What did the system understand and search?
3. What evidence is found/missing and what happens next?

3. COLORS
Use a professional blue/indigo primary.
White/light neutral background.
Dark neutral text.
Green for completed/validated.
Amber for attention/missing.
Red for errors/rejection.
Status must also use text/icons, not color alone.

4. TYPOGRAPHY
Recommended: Inter or system sans-serif.
Page title: 24–30px.
Section heading: 18–22px.
Body: 14–16px.
Meta: 12–13px.
Tables: 13–14px.

5. COMPONENT STYLE
8–10px radius.
Light borders.
Subtle shadows.
Cards for major workflow stages.
Tables for evidence.
Badges for status.
Progress/timeline for retrieval.
No heavy gradients or excessive visual effects.

6. AUDIT REQUEST SCREEN
Header: Automated Audit Evidence Retrieval
Subtitle: Submit an audit requirement and track evidence retrieval.

Main:
Large text area.
Example:
“Provide AP Cost Drill for August 2026, SOB 101, NAC 5000–5999.”

CTA:
Start Retrieval

Below:
Four supported-use-case cards.

11. ACCESSIBILITY
- Strong contrast.
- Labels + icons, not color only.
- Keyboard focus.
- Clear form labels.
- Clear error messages.
- Visible progress.
- Readable tables.

12. RESPONSIVE
Desktop-first.
Tablet: stack cards and allow table scrolling.
Mobile: one column, compact navigation, large CTA, evidence cards where tables are too wide.

- Login/signup
- Profile/account management
- Billing
- Deployment pages
- Complex admin settings
- Real enterprise data
