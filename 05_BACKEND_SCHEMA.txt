DOCUMENT 05 — BACKEND SCHEMA

Project: Automated Audit Evidence Retrieval
Version: 1.0

Authentication and RLS are intentionally excluded.

1. DATABASE LAYOUT

A. Mock source databases:
- db01.sqlite
- db02.sqlite
- db03.sqlite
- db04.sqlite

These simulate different enterprise sources.

B. Application state database:
- app_state.sqlite

Stores request/workflow/retrieval/validation/package state.

6. DATABASE REGISTRY

The POC does NOT map evidence types to individual systems.

The registry only defines searchable sources and search order:

[
  {
    "database_id": "DB-01",
    "name": "Mock Database 01",
    "path": "databases/db01.sqlite",
    "enabled": true,
    "search_order": 1
  },
  {
    "database_id": "DB-02",
    "name": "Mock Database 02",
    "path": "databases/db02.sqlite",
    "enabled": true,
    "search_order": 2
  }
]

9. API CONTRACTS

POST /api/audit-requests
Request:
{"query": "string"}

Response:
{"request_id": "AUD-001", "status": "RECEIVED"}

GET /api/audit-requests/{request_id}
Returns request/workflow state.

POST /api/audit-requests/{request_id}/run
Starts/continues workflow.

POST /api/audit-requests/{request_id}/retry
Triggers retry.

POST /api/audit-requests/{request_id}/review
Request:
{"action": "APPROVE", "comment": "Reviewed"}

GET /api/audit-requests/{request_id}/package
Returns package metadata.

GET /api/use-cases
Returns POC use cases.

11. DATA MODEL PRINCIPLE
The mock source schemas are intentionally generic and are used to simulate multiple enterprise sources. The application state schema is separate so workflow history remains independent from the source-system mocks.
