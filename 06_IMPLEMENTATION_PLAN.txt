Goal: Parse auditor language to structured JSON.

Prompt must:
- Classify only to UC-01…UC-04/UNSUPPORTED.
- Extract only supported values.
- Never invent values.
- Return JSON only.
- Report ambiguity/confidence.

Tasks:
1. Configure Groq.
2. Build LangChain prompt.
3. Define Pydantic output schema.
4. Handle model errors.
5. Add representative test queries.

Done:
- Representative queries classify correctly.
- Missing required inputs are visible.
- Unsupported requests are rejected cleanly.

PHASE 7 — MCP LAYER
Goal: Provide tool-based database access.

Tasks:
1. Implement MCP server/tool module.

Done:

- No direct DB access from agent code.

PHASE 8 — RETRIEVAL AGENT
Goal: Perform sequential multi-database search.

Tasks:
1. Receive required evidence + parameters.
2. Search DBs in configured order.
3. Track found/missing.
4. Stage documents.
5. Add newly discovered identifiers to search context.
6. Skip already found evidence.
7. Stop when complete or all sources exhausted.
8. Record attempts.
9. Return retrieval summary.

Done:
- Evidence can be found across multiple DBs.
- Missing list is accurate.
- Search state is visible.

PHASE 9 — EVIDENCE STAGING
Goal: Centralize request-specific retrieved files.

Tasks:
1. Create evidence_staging/{request_id}/.
2. Copy files.
3. Store metadata.
4. Store source DB/document ID.
5. Use deterministic safe filenames.

Done:
- Every retrieved file is traceable.
- Original source is not changed.

PHASE 10 — VALIDATION ENGINE
Goal: Validate completeness and matching.

Checks:
- Required item found.
- Correct document type.
- Vendor match.
- Invoice match.
- Period match.
- SOB/NAC/report type match where relevant.

Statuses:
COMPLETE
INCOMPLETE
NEEDS_REVIEW
ERROR

Done:
- Positive dataset returns COMPLETE.
- Missing dataset returns INCOMPLETE.
- Wrong identifier produces a clear issue.

PHASE 11 — RETRY / RE-CHECK
Goal: Close the loop on missing evidence.

Tasks:
1. Read missing evidence.
2. Retry remaining sources.
3. Use alternate strong identifiers from retrieved metadata.
4. Bound retry count.
5. Re-run validation.
6. Stop as NEEDS_REVIEW if not resolved.

Done:
- At least one missing item is found through retry.
- Infinite loops cannot occur.

FINAL DEFINITION OF DONE
The POC is complete when all four use cases work end-to-end, the LLM output is schema-valid, required evidence comes from controlled configuration, retrieval happens through MCP across SQLite mock databases, evidence is staged and validated, at least one retry works, a package is generated, reviewer approval works, and the complete system runs locally without auth or deployment infrastructure.
